## Fix #7 — Agent面板非实时 + done假卡死 (commit c0b9569)

### 问题A: Agent事件不是逐条实时滚出，分析完成才一并显示
- **诊断**: `curl -i -N` 直连 :8888 与经 :3000 rewrite 双路径，均显示 backend SSE **真实时推送**（agent_progress 间隔 5-10s 流出），headers 完整：`Content-Type: text/event-stream` / `X-Accel-Buffering: no` / `Transfer-Encoding: chunked`。
- **根因**: frontend `client.ts` SSE parser 按 `\n` split 后处理。当 TCP chunk 在 `data:` 行中间被切断（典型场景：高频事件 burst），下一轮 lines 第一行变成 data 续片，前一轮的 `event:` 行已被消费但 eventType 在 for 循环外作用域被丢弃，导致**事件丢失**或**延迟到下个完整块才被识别**。
- **修复**: 改为 SSE 规范的"按 `\n\n` 空行分隔事件块"派发模式 — `dispatchBlock(block)` 整块解析 event/data，跨 chunk 正确缓冲到 buffer 中，杜绝边界丢字段。
- **文件**: `frontend/src/lib/api/client.ts` (75-145行)

### 问题B: Agent面板已"6/6 完成"但 chat 区域永远显示 "(正在生成...)"
- **诊断**: agent-analyze 路径**不发 token 事件**（仅 agent_progress / tool_call_* / artifact / done）→ `fullContentBuffer = ''` & `streamingContent = ''` → `onDone` 创建 `content: ''` 的 assistantMsg 入 store → `message-bubble.tsx:107-110` 三元运算 fallback 渲染字面量 "(正在生成...)"。setStreaming(false) 已正确触发，但消息内容为空导致占位永久残留（与 isStreaming 无关）。
- **修复**: 
  1. `use-chat-stream.ts onDone`: finalContent 为空时，从 `artifacts[].decision_card` + `execution_log` 自动合成 markdown 总结（含建议操作、置信度、风险等级、价位、推理理由）
  2. `onClose` 兜底同步增加 artifacts-only 时的占位消息
  3. `message-bubble.tsx`: fallback 文案优化为"分析已完成，请查看下方决策卡片"（含 artifacts 时）/"（无文本输出）"（兜底）
- **文件**: `frontend/src/lib/hooks/use-chat-stream.ts` (148-200行) / `frontend/src/lib/types/index.ts` (StreamDone 扩展) / `frontend/src/components/chat/message-bubble.tsx` (107-115行)

## 第三批 fix9 — 消除API响应裸NaN/Infinity (2026-04-14 17:30 +08:00)

### 现象
前端 console 持续刷:
`[conversation-sidebar] 加载对话消息失败: SyntaxError: Unexpected token 'N', ..."s_margin":NaN,"net_p"... is not valid JSON`

### 根因
Flask 3.0 `jsonify` 默认 `allow_nan=True`, 把 Python float NaN/Infinity 输出为裸字面 `NaN`/`Infinity`(非标 JSON), 前端 `fetch().json()` / `JSON.parse()` 直接抛 SyntaxError。受影响端点为所有走 Flask 原生 `jsonify` 的路由(125+ 处), 包括 `/api/conversations/<id>`。

### 修复
**后端(7779ca6)** `app/web/web_server.py`:
- `custom_jsonify` 内 `json.dumps` 追加 `allow_nan=False` (L531 附近)
- 新增全局 `NanSafeJSONProvider` 覆盖 `app.json`, 使所有 `jsonify` 调用统一走 NaN-safe 路径 (L542-560)

**前端(448d2c0)** `frontend/src/lib/api/client.ts`:
- 新增 `safeJSONParse(text)` 用 `\bNaN\b` / `\bInfinity\b` / `\b-Infinity\b` 正则替换为 `null`
- `ApiClient.get` / `ApiClient.post` 改走 `res.text()` + `safeJSONParse` (L28-39 附近) — 所有调用点自动受益

### 验证证据
```

curl /api/conversations/conv_c84f32088e02 | grep -c '\bNaN\b'  # = 2
# 重启后端后

python3 -m json.tool < /tmp/conv_after2.json  # valid JSON OK
```
